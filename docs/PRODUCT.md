# 产品设计与验收映射

## 核心任务

一名研究员选择沪深300和20日区间，想知道“指数表现是否足以代表市场整体状态”。产品先制定数据计划，调用日线工具，检查时点和完整性，再展示事实、归纳、不确定判断与原始证据。研究员可以发现缺失、追问风格或风险，导出有证据链的研究快照。

## 主链路

选择指数/区间/来源 → 显示研究进度 → 获取指数与比较指数日线 → 剔除未收盘与未来数据 → 样本/冲突/过期校验 → 计算指标 → 形成证据对象 → 可选模型归纳 → 结构/引用/数字/边界检查 → 展示状态与待验证条件 → 继续追问/保存/导出。

模型失败时显示模型失败标识并保留规则解释；主指数取数失败时停止结论；比较指数缺失时只保留可核验的局部证据，不生成风格表现差。

## 信息结构

| 区域 | 用户得到什么 |
|---|---|
| 研究范围 | 指数、区间、明确的数据源与演示场景 |
| 观察状态 | 结论、时点、置信度与“非概率”解释 |
| 事实/归纳/不确定 | 每条有证据ID，明确认识层级 |
| 图表与指标 | 历史价格结构、均线偏离、量比、实现波动率 |
| 证据完整度 | 七维已覆盖/代理/缺失，不把缺失填成正常 |
| 状态切换 | 具体可检验阈值、当前可评估性、所缺数据 |
| 证据中心 | 来源端点、单位、时点、统计口径与原始字段 |
| 研究计划与调用记录 | 工具名、标的、耗时、来源、成功/失败 |
| 继续追问 | 风格、风险、行业或历史证据需求 |
| 保存/导出 | 本浏览器快照、JSON完整证据、Markdown报告 |

## 24小时范围取舍

优先实现可运行闭环、真实指数来源、可追溯证据和异常透明度。未取得授权的宽度/估值/资金/事件数据不编造。模型凭证可在会话设置或部署环境中配置，未配置不会隐藏成“AI已运行”。

## 验收对应

1. 市场框架与工具主链路：`engine.js` 的 `planFor/buildReport` 与 `server.js` 的 `loadIndex/research`。
2. 输出结论、证据、时点、置信度和切换条件：报告对象及工作台。
3. Web URL、源码、README：托管产品、GitHub镜像与项目README。
4. AI使用、验证与测试：`AI_RECORD.md`、`TESTING.md`、自动化测试源码。
5. 关键结论追溯：E1–E7弹窗及完整JSON导出，包含原始字段与公式。

完整AI在线模式仍需有效凭证才能验收，这是明确的集成条件。真实市场七维覆盖仍不足，当前交付是可运行、边界透明的研究MVP，而非全量数据的生产投研系统。
