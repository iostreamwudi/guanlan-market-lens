## 产品运行中的AI

OpenAI API只在配置有效Key后调用。它读取工具返回的证据对象，生成带引用的“归纳/不确定”说明。事实、指标、来源和时点由代码保留。模型没有任意网络访问或交易工具。

请求使用 `store:false` 和严格JSON Schema；应用校验引用集合、未知数字与越界措辞。接口异常、模型拒绝、结构无效、引用无效或越界时，丢弃该模型输出并明确显示失败。

无凭证环境中没有成功调用真实大模型；测试中的成功/失败响应均为mock，不作为真实模型效果证明。

## 发现并修正的问题

| 问题 | 证据与修正 | 验证 |
|---|---|---|
| 扶摇毫秒时间戳直接转UTC日期可能前移一天 | 官方示例 `1716134400000` 为北京时间2024-05-20零点、UTC前一天16点；先加8小时再取日期 | 北京时间戳测试通过 |
| 输入规则遗漏“保证收益” | 首次测试21项有1项失败，增加“保证/承诺…收益”拦截 | 后续21项全部通过 |
| 证据单位显示可能重复或缺失 | 事实值自带%时不再重复，宽度/估值纯数字保留%单位 | 浏览器与源码检查 |
| “不确定”标签换行 | 标签禁止换行并增加标签列宽度 | 页面视觉复核 |
| 原型链字段被当作合法指数 | 使用 `Object.hasOwn` 检查白名单 | 参数测试与代码复核 |
| 演示估值样本口径不够精确 | 明确60个月内50个有效月末样本，31/50=62% | 原始字段与说明一致 |

## 防止AI制造伪证据

数据源模式不会静默切换。没有扶摇Key不宣称已经调用；公开接口失败不回退演示；模型未启用不宣称模型生成；没有事件原文不生成新闻或因果解释；宽基代理不冒充行业/纯因子归因。

## 局限

规则检查并不完备，存在同义表达绕过与模型语义错误风险。数字出现在证据集合中，不等于该数值在当前句子中被正确解释；有效引用也不自动证明推论成立。需要进一步人工标注评估、模型真实集成测试和供应商授权数据校验。
